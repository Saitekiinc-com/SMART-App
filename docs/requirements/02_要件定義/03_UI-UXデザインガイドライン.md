# UI/UXデザインガイドライン

## 1. デザインコンセプト

- **直感的かつモダン**:
  - エンジニアが日常的に使いたくなる、シンプルで洗練されたデザイン
  - ダークモード対応を前提とする
- **入力負荷の軽減**:
  - ウィザード形式による段階的な入力で、ユーザーの認知負荷を下げる
- **可視化**:
  - ステータス（未着手/進行中/完了）や進捗率を色やグラフで直感的に表現する

## 2. バリデーション要件

### 2.1 基本方針

- **クライアントサイド**: リアルタイムバリデーション（フォーカスアウト時）で即座にフィードバック
- **サーバーサイド**: すべての入力を再検証し、データの整合性を担保

### 2.2 エラー表示

- **表示位置**: 入力フィールドの直下に赤字で表示
- **ハイライト**: エラーのあるフィールドを赤枠で囲む
- **挙動**: 正しい値を入力すると即座にエラー表示が消えること

### 2.3 ウィザードの挙動

- **次へボタン**: エラーがある場合は非活性化（押せない状態）にする
- **戻るボタン**: 入力内容を保持したまま前のステップへ遷移可能にする
- **キャンセル**: 確認ダイアログを表示し、誤操作によるデータ消失を防ぐ

### 2.4 エラーメッセージ一覧

| 項目 | エラー条件 | メッセージ |
| --- | --- | --- |
| タイトル | 未入力 | タイトルを入力してください |
| タイトル | 文字数超過 | 100文字以内で入力してください（現在{n}文字） |
| 具体的 (Specific) | 未入力/短すぎる | 具体的な内容を10文字以上入力してください |
| 具体的 (Specific) | 文字数超過 | 500文字以内で入力してください（現在{n}文字） |
| 測定可能 (Measurable) | 未入力 | 測定可能な基準を入力してください |
| 測定可能 (Measurable) | 文字数超過 | 200文字以内で入力してください（現在{n}文字） |
| 達成可能 (Achievable) | 未チェック | 達成可能性を確認してください |
| 関連性 (Relevant) | 未入力 | 関連性を入力してください |
| 関連性 (Relevant) | 文字数超過 | 200文字以内で入力してください（現在{n}文字） |
| 期限 (Time-bound) | 未入力/過去日 | 未来の日付を選択してください |
| アプローチ | 空 | 少なくとも1つの手順を追加してください |
| アプローチ | 文字数超過 | 各手順は100文字以内で入力してください |

### 2.5 エラーハンドリング

- **サーバーエラー**: エラートースト通知（画面上部に5秒間表示）を行う
- **データ保持**: エラー発生時も入力内容は可能な限り保持する
- **リトライ**: エラーダイアログにリトライボタンを表示する
