# 06_非機能要件定義書

## 1. 性能要件

- **レスポンスタイム**:
  - 画面表示は3秒以内に完了すること
  - API応答時間は1秒以内を目標とする
- **処理量**:
  - ダッシュボードのゴール一覧は50件まで一度に表示しても遅延しないこと

## 2. 可用性要件

- **稼働率**: 99%以上を目標とする
- **計画停止**: メンテナンス等による計画停止時は、事前にユーザーへ通知する仕組みを設ける

## 3. セキュリティ要件

- **認証・認可**:
  - パスワードはハッシュ化して保存する
  - 認証トークンには有効期限を設定する
  - チームデータは所属メンバーのみアクセス可能とする（認可制御）
  - 招待トークンは推測不可能なランダム文字列（UUID等）を使用する
- **通信**: HTTPS通信を必須とする
- **API**: 全てのエンドポイントで適切な権限チェックを実施する

## 4. 保守性・運用要件

- **ログ監視**:
  - アプリケーションログを出力・保存する
  - エラー発生時は管理者へ通知する仕組み（Slack通知等）を設ける
- **バックアップ**:
  - データベースの定期バックアップ（日次等）を実施する

## 5. 技術スタック（制約条件）

- **Frontend**: React (Next.js) + TypeScript
- **Backend**: Next.js API Routes (TypeScript) または Node.js + Express/NestJS (TypeScript)
- **Database**: PostgreSQL (Prisma ORM推奨)
- **Auth**: NextAuth.js (Auth.js)
