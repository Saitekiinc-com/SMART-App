# 制約・前提条件

本フェーズ（MVP）の開発範囲と、前提・制約をまとめたものです。

## 1. 開発スコープ（対象とするもの）

以下の機能を本フェーズで開発する。

- **チーム作成・管理**（リーダーによるチーム作成、招待リンク、権限管理）
- **SMARTゴール作成ウィザード**（6ステップ、バリデーション）
- **ゴール一覧表示**（ステータス・投票数による表示）
- **投票機能**（1ゴール1票、投票数表示）
- **通知機能**（アプリ内通知、期限リマインダー）
- **完了機能**（ゴールの達成/完了ステータス更新）

## 2. スコープ外（本フェーズでは行わないこと）

- メール通知・Slack連携などの外部通知
- ユーザー単位の「グローバルなロール」管理（ロールはチームごとの TeamMember で管理）
- 上記一覧に含まれない新機能

## 3. 技術スタック（推奨）

| 区分 | 技術 |
| --- | --- |
| **Frontend** | React (Next.js) + TypeScript |
| **Backend** | Next.js API Routes (TypeScript) または Node.js + Express/NestJS (TypeScript) |
| **Database** | PostgreSQL (Prisma ORM推奨) |
| **Auth** | NextAuth.js (Auth.js) |

## 4. 前提条件

- ユーザーはメール/パスワードまたはGoogleでサインアップ・ログインする。
- チームはリーダーのみが作成でき、作成者がそのチームのリーダーとなる。
- 招待はリーダーのみが発行でき、招待リンクは7日間有効・1回使用限り。
- ゴールのステータスは TODO → IN_PROGRESS → DONE で管理する。
- 投票は未着手（TODO）のゴールを対象とし、1ユーザー1ゴール1票。

## 5. 制約事項

- **性能**: 画面表示3秒以内、API応答1秒以内を目標。ダッシュボードのゴール一覧は50件まで一度に表示。
- **セキュリティ**: パスワードはハッシュ化、通信はHTTPS、チームデータは所属メンバーのみアクセス可。招待トークンは推測困難なランダム文字列。
- **可用性**: 稼働率99%以上を目標。計画停止時は事前にユーザーへ通知。
- **保守**: アプリログ出力、エラー時は管理者へ通知、DBの定期バックアップを実施。
