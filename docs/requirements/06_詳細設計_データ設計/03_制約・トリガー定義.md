# 03_制約・トリガー定義

## 目的

データ整合性を保つための制約とトリガーを定義する。
実装担当者が「迷わずにSQLを書き、制約とトリガーを作成できる」レベルを目指す。

---

## 1. CHECK制約一覧

| テーブル名 | カラム名 | 制約名 | 条件式 | 補足 |
|------------|----------|--------|--------|------|
| team_members | role | team_members_role_check | role IN ('leader', 'member') | ロールはleaderまたはmemberのみ |
| smart_goals | status | smart_goals_status_check | status IN ('TODO', 'IN_PROGRESS', 'DONE') | ステータスはTODO/IN_PROGRESS/DONEのみ |
| smart_goals | vote_count | smart_goals_vote_count_check | vote_count >= 0 | 投票数は0以上 |
| notifications | type | notifications_type_check | type IN ('GOAL_CREATED', 'STATUS_CHANGED', 'DEADLINE_REMINDER', 'GOAL_COMPLETED') | 通知種別の制限 |

### CHECK制約のSQL定義

```sql
-- team_members.role
ALTER TABLE team_members ADD CONSTRAINT team_members_role_check
  CHECK (role IN ('leader', 'member'));

-- smart_goals.status
ALTER TABLE smart_goals ADD CONSTRAINT smart_goals_status_check
  CHECK (status IN ('TODO', 'IN_PROGRESS', 'DONE'));

-- smart_goals.vote_count
ALTER TABLE smart_goals ADD CONSTRAINT smart_goals_vote_count_check
  CHECK (vote_count >= 0);

-- notifications.type
ALTER TABLE notifications ADD CONSTRAINT notifications_type_check
  CHECK (type IN ('GOAL_CREATED', 'STATUS_CHANGED', 'DEADLINE_REMINDER', 'GOAL_COMPLETED'));
```

## 2. UNIQUE制約一覧

| テーブル名 | カラム名（複数可） | 制約名 | 補足 |
|------------|---------------------|--------|------|
| users | email | users_email_key | メールアドレスの重複を防止 |
| team_members | (team_id, user_id) | team_members_team_id_user_id_key | 1ユーザーは1チームに1回のみ所属可能 |
| votes | (goal_id, user_id) | votes_goal_id_user_id_key | 1ユーザーは1ゴールに1票まで |
| invitations | token | invitations_token_key | 招待トークンの重複を防止 |

### UNIQUE制約のSQL定義

```sql
-- users.email
ALTER TABLE users ADD CONSTRAINT users_email_key UNIQUE (email);

-- team_members(team_id, user_id)
ALTER TABLE team_members ADD CONSTRAINT team_members_team_id_user_id_key
  UNIQUE (team_id, user_id);

-- votes(goal_id, user_id)
ALTER TABLE votes ADD CONSTRAINT votes_goal_id_user_id_key
  UNIQUE (goal_id, user_id);

-- invitations.token
ALTER TABLE invitations ADD CONSTRAINT invitations_token_key UNIQUE (token);
```

## 3. FOREIGN KEY制約一覧

| テーブル名 | カラム名 | 制約名 | 参照先テーブル | 参照先カラム | ON DELETE | ON UPDATE | 補足 |
|------------|----------|--------|----------------|--------------|-----------|-----------|------|
| teams | created_by_id | teams_created_by_id_fkey | users | id | RESTRICT | CASCADE | 作成者が削除されるとチームも削除できない |
| team_members | team_id | team_members_team_id_fkey | teams | id | CASCADE | CASCADE | チーム削除時はメンバー情報も削除 |
| team_members | user_id | team_members_user_id_fkey | users | id | CASCADE | CASCADE | ユーザー削除時はメンバー情報も削除 |
| smart_goals | team_id | smart_goals_team_id_fkey | teams | id | CASCADE | CASCADE | チーム削除時はゴールも削除 |
| smart_goals | owner_id | smart_goals_owner_id_fkey | team_members | id | RESTRICT | CASCADE | 所有者が削除されるとゴールも削除できない |
| approaches | goal_id | approaches_goal_id_fkey | smart_goals | id | CASCADE | CASCADE | ゴール削除時はアプローチも削除 |
| votes | goal_id | votes_goal_id_fkey | smart_goals | id | CASCADE | CASCADE | ゴール削除時は投票も削除 |
| votes | user_id | votes_user_id_fkey | users | id | CASCADE | CASCADE | ユーザー削除時は投票も削除 |
| invitations | team_id | invitations_team_id_fkey | teams | id | CASCADE | CASCADE | チーム削除時は招待も削除 |
| invitations | inviter_id | invitations_inviter_id_fkey | users | id | RESTRICT | CASCADE | 招待者が削除されると招待も削除できない |
| notifications | user_id | notifications_user_id_fkey | users | id | CASCADE | CASCADE | ユーザー削除時は通知も削除 |
| notifications | goal_id | notifications_goal_id_fkey | smart_goals | id | CASCADE | CASCADE | ゴール削除時は通知も削除（NULL可） |

### FOREIGN KEY制約のSQL定義

（02_テーブル定義詳細のCREATE TABLEに含まれるため、ここではALTER TABLEによる追加例のみ記載。通常はCREATE TABLE時に定義する。）

```sql
-- 例: teams.created_by_id
ALTER TABLE teams ADD CONSTRAINT teams_created_by_id_fkey
  FOREIGN KEY (created_by_id) REFERENCES users(id)
  ON DELETE RESTRICT ON UPDATE CASCADE;
-- （他の外部キーも同様）
```

## 4. トリガー定義

### updated_at自動更新トリガー

`updated_at`カラムを持つテーブルに対して、UPDATE時に自動的に現在時刻を設定するトリガーを定義する。

#### 対象テーブル

- `users`
- `teams`
- `smart_goals`

#### トリガー定義表

| トリガー名 | 対象テーブル | 実行タイミング | 処理内容 | 補足 |
|------------|--------------|----------------|----------|------|
| update_users_updated_at | users | BEFORE UPDATE | updated_at = CURRENT_TIMESTAMP | 更新時に自動的に現在時刻を設定 |
| update_teams_updated_at | teams | BEFORE UPDATE | updated_at = CURRENT_TIMESTAMP | 同上 |
| update_smart_goals_updated_at | smart_goals | BEFORE UPDATE | updated_at = CURRENT_TIMESTAMP | 同上 |

#### トリガー関数（PostgreSQL）

```sql
-- updated_at自動更新用の共通関数
CREATE OR REPLACE FUNCTION update_updated_at_column()
RETURNS TRIGGER AS $$
BEGIN
    NEW.updated_at = CURRENT_TIMESTAMP;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;
```

#### トリガー作成SQL

```sql
-- users.updated_at
CREATE TRIGGER update_users_updated_at
    BEFORE UPDATE ON users
    FOR EACH ROW
    EXECUTE FUNCTION update_updated_at_column();

-- teams.updated_at
CREATE TRIGGER update_teams_updated_at
    BEFORE UPDATE ON teams
    FOR EACH ROW
    EXECUTE FUNCTION update_updated_at_column();

-- smart_goals.updated_at
CREATE TRIGGER update_smart_goals_updated_at
    BEFORE UPDATE ON smart_goals
    FOR EACH ROW
    EXECUTE FUNCTION update_updated_at_column();
```

※ PostgreSQL 11以降では `EXECUTE FUNCTION`、それ以前では `EXECUTE PROCEDURE` を使用する場合があります。

## 5. カスタムバリデーション（アプリケーション層）

以下の項目はデータベースの制約ではなく、アプリケーション層で制御する。

| テーブル名 | カラム名 | バリデーションルール | 補足 |
|------------|----------|----------------------|------|
| smart_goals | specific | 10〜500文字 | アプリ層で文字数チェック |
| smart_goals | measurable | 最大200文字 | アプリ層で文字数チェック |
| smart_goals | relevant | 最大200文字 | アプリ層で文字数チェック |
| smart_goals | deadline | 未来の日付 | アプリ層で日付チェック |
| approaches | - | 最大10件 | アプリ層で件数チェック（1ゴールあたり） |
| invitations | expires_at | 作成日時+7日 | アプリ層で計算・設定 |

### バリデーション実装方針

- **フロントエンド**: リアルタイムバリデーション（入力時）
- **バックエンドAPI**: リクエスト受信時のバリデーション
- **データベース**: 基本的なNOT NULL、型チェックのみ（文字数制限等はアプリ層で制御）

## 6. データ整合性ルール

### ビジネスルール

| ルール | 説明 | 実装方法 |
|--------|------|----------|
| **1ユーザー1チーム1回のみ所属** | 同じユーザーが同じチームに複数回所属することはできない | UNIQUE制約: `team_members(team_id, user_id)` |
| **1ユーザー1ゴール1票まで** | 同じユーザーが同じゴールに複数回投票することはできない | UNIQUE制約: `votes(goal_id, user_id)` |
| **メールアドレス重複不可** | 同じメールアドレスで複数のアカウントを作成できない | UNIQUE制約: `users.email` |
| **招待トークン重複不可** | 同じトークンで複数の招待を作成できない | UNIQUE制約: `invitations.token` |
| **ロールはleaderまたはmemberのみ** | チームメンバーのロールはleader/member以外は設定できない | CHECK制約: `team_members.role` |
| **ステータスはTODO/IN_PROGRESS/DONEのみ** | ゴールのステータスは指定された3つのみ | CHECK制約: `smart_goals.status` |
| **投票数は0以上** | 投票数が負の値になることはない | CHECK制約: `smart_goals.vote_count` |
| **通知種別の制限** | 通知種別は指定された4つのみ | CHECK制約: `notifications.type` |

### 参照整合性ルール

| ルール | 説明 | 実装方法 |
|--------|------|----------|
| **チーム作成者の存在** | チームを作成したユーザーが存在する必要がある | FOREIGN KEY制約: `teams.created_by_id` (ON DELETE RESTRICT) |
| **ゴール所有者の存在** | ゴールの所有者（team_members）が存在する必要がある | FOREIGN KEY制約: `smart_goals.owner_id` (ON DELETE RESTRICT) |
| **招待者の存在** | 招待を発行したユーザーが存在する必要がある | FOREIGN KEY制約: `invitations.inviter_id` (ON DELETE RESTRICT) |
| **カスケード削除** | 親レコード削除時に子レコードも自動削除 | FOREIGN KEY制約: ON DELETE CASCADE |
| **カスケード更新** | 親レコードの主キー更新時に子レコードも自動更新 | FOREIGN KEY制約: ON UPDATE CASCADE |

### データ整合性の補足

- **中間テーブルの整合性**: `team_members`と`votes`は中間テーブルとして、多対多の関係を適切に管理
- **論理削除なし**: 物理削除を基本とする（論理削除は不要）
- **タイムスタンプの自動更新**: `updated_at`はトリガーで自動更新（アプリ層で明示的に設定する必要はない）
