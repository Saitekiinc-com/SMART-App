# 05_フロント側処理フロー

## 目的

主要な操作におけるフロント側の詳細な処理フローを記載する。

---

## S-01: ログイン/サインアップボタン押下時の処理フロー

```plain text
1. ボタンクリック
2. クライアント側バリデーション実行
   - メールアドレス形式チェック
   - パスワード長・形式チェック（サインアップ時）
   - パスワード一致チェック（サインアップ時）
3. バリデーションエラー時
   → エラーメッセージをフィールド直下に表示
   → エラーフィールドを赤枠でハイライト
   → 処理終了
4. バリデーション通過時
   → ローディング表示（ボタン内スピナー）
   → API呼び出し（POST /api/auth/login または /api/auth/signup）
5. APIレスポンス処理
   - 成功時（200）
     → 認証トークンをlocalStorageに保存
     → ユーザー情報を取得（GET /api/users/me）
     → 所属チーム数を確認
     → 所属チームが1つ: S-04 チームダッシュボードへ遷移
     → 所属チームが2つ以上: S-03 チーム選択へ遷移
   - エラー時（400, 401, 500等）
     → エラーメッセージをエラー表示領域に表示
     → ローディング非表示
     → 処理終了
6. 画面遷移時
   → ローディング非表示
   → トースト通知表示（任意）
```

## S-05: 保存ボタン（ゴール作成）押下時の処理フロー

```plain text
1. 保存ボタンクリック（最終ステップ）
2. クライアント側バリデーション実行
   - タイトル: 1〜100文字
   - 具体的: 10〜500文字
   - 測定可能: 1〜200文字
   - 関連性: 1〜200文字
   - 期限: 未来の日付
   - アプローチ: 最大10件、各1〜200文字
3. バリデーションエラー時
   → エラーメッセージを各フィールド直下に表示
   → エラーフィールドを赤枠でハイライト
   → 処理終了
4. バリデーション通過時
   → ローディング表示（全画面またはボタン内スピナー）
   → リクエストボディ作成（title, specific, measurable, achievable, relevant, deadline, owner_id, approaches）
   → API呼び出し（POST /api/goals）
5. APIレスポンス処理
   - 成功時（200, 201）
     → ローディング非表示
     → トースト通知表示（「ゴールを作成しました」）
     → S-04 チームダッシュボードへ遷移
   - エラー時（400, 401, 403, 500等）
     → ローディング非表示
     → エラーメッセージをトースト通知またはエラー表示領域に表示
     → 画面に留まる（遷移しない）
6. 画面遷移時
   → ダッシュボードのゴール一覧を再取得（GET /api/teams/{teamId}/goals）
```

## S-07: 保存ボタン（ゴール編集）押下時の処理フロー

```plain text
1. 保存ボタンクリック（最終ステップ）
2. クライアント側バリデーション実行
   - S-05と同様のバリデーション
   - ステータス: TODO / IN_PROGRESS / DONE のいずれか
3. バリデーションエラー時
   → エラーメッセージを各フィールド直下に表示
   → エラーフィールドを赤枠でハイライト
   → 処理終了
4. バリデーション通過時
   → ローディング表示
   → リクエストボディ作成（既存のgoal_idを含む）
   → API呼び出し（PUT /api/goals/{goalId}）
5. APIレスポンス処理
   - 成功時（200）
     → ローディング非表示
     → トースト通知表示（「ゴールを更新しました」）
     → S-06 ゴール詳細へ遷移
   - エラー時（400, 401, 403, 404, 500等）
     → ローディング非表示
     → エラーメッセージをトースト通知またはエラー表示領域に表示
     → 画面に留まる（遷移しない）
6. 画面遷移時
   → ゴール詳細のデータを再取得（GET /api/goals/{goalId}）
```

## S-04: 投票ボタン押下時の処理フロー

```plain text
1. 投票ボタンクリック（ゴールカード上またはゴール詳細）
2. クライアント側チェック
   - ゴールステータスが「未着手（TODO）」であること
   - 既に投票済みでないこと（トグル動作）
3. チェック通過時
   → ローディング表示（ボタン内スピナーまたは投票数バッジ）
   → API呼び出し（POST /api/goals/{goalId}/votes または DELETE /api/goals/{goalId}/votes）
4. APIレスポンス処理
   - 成功時（200, 201, 204）
     → ローディング非表示
     → 投票数を更新（+1 または -1）
     → 投票ボタンの状態を更新（投票済み/未投票）
     → 画面遷移なし（その場で更新）
   - エラー時（400, 401, 403, 500等）
     → ローディング非表示
     → トースト通知でエラーメッセージ表示
     → 画面に留まる
```

## S-06: 削除ボタン押下時の処理フロー

```plain text
1. 削除ボタンクリック
2. 確認ダイアログ表示
   - メッセージ: 「このゴールを削除しますか？この操作は取り消せません。」
   - 確定ボタン、キャンセルボタン
3. キャンセル時
   → ダイアログ閉じる
   → 処理終了
4. 確定時
   → ローディング表示（全画面またはボタン内スピナー）
   → API呼び出し（DELETE /api/goals/{goalId}）
5. APIレスポンス処理
   - 成功時（200, 204）
     → ローディング非表示
     → トースト通知表示（「ゴールを削除しました」）
     → S-04 チームダッシュボードへ遷移
   - エラー時（401, 403, 404, 500等）
     → ローディング非表示
     → トースト通知でエラーメッセージ表示
     → 画面に留まる（S-06 ゴール詳細）
6. 画面遷移時
   → ダッシュボードのゴール一覧を再取得（GET /api/teams/{teamId}/goals）
```

## S-09: 保存ボタン（チーム設定）押下時の処理フロー

```plain text
1. 保存ボタンクリック
2. クライアント側バリデーション実行
   - チーム名: 1〜50文字
   - チーム説明: 最大200文字（任意）
3. バリデーションエラー時
   → エラーメッセージを各フィールド直下に表示
   → エラーフィールドを赤枠でハイライト
   → 処理終了
4. バリデーション通過時
   → ローディング表示（ボタン内スピナー）
   → リクエストボディ作成（name, description optional）
   → API呼び出し（PUT /api/teams/{teamId}）
5. APIレスポンス処理
   - 成功時（200）
     → ローディング非表示
     → トースト通知表示（「チーム情報を更新しました」）
     → 画面内でチーム情報を更新（画面遷移なし）
   - エラー時（400, 401, 403, 500等）
     → ローディング非表示
     → トースト通知でエラーメッセージ表示
     → 画面に留まる
```

## S-06: ステータス変更時の処理フロー

```plain text
1. ステータス変更UIクリック/選択
2. クライアント側チェック
   - 新しいステータス値（TODO / IN_PROGRESS / DONE）
3. ローディング表示（ステータスバッジ内スピナー）
4. API呼び出し（PATCH /api/goals/{goalId}）
   - リクエストボディ: {status: string}
5. APIレスポンス処理
   - 成功時（200）
     → ローディング非表示
     → ステータス表示を更新
     → ステータスがDONEの場合、フィードバック入力欄を表示
     → 画面遷移なし（その場で更新）
   - エラー時（400, 401, 403, 500等）
     → ローディング非表示
     → トースト通知でエラーメッセージ表示
     → ステータスを元の値に戻す
```

## S-06: アプローチチェックボックス変更時の処理フロー

```plain text
1. アプローチチェックボックスクリック
2. 完了状態を切り替え（true ↔ false）
3. ローディング表示（チェックボックス内スピナー）
4. API呼び出し（PATCH /api/approaches/{approachId}）
   - リクエストボディ: {completed: boolean}
5. APIレスポンス処理
   - 成功時（200）
     → ローディング非表示
     → チェックボックス状態を更新
     → 進捗%を再計算・表示更新
     → 画面遷移なし（その場で更新）
   - エラー時（400, 401, 403, 500等）
     → ローディング非表示
     → トースト通知でエラーメッセージ表示
     → チェックボックスを元の状態に戻す
```

## 共通処理フロー

### ローディング表示

- **全画面ローディング**: スケルトンスクリーン表示
- **ボタン内ローディング**: ボタン内にスピナー表示、ボタンを無効化
- **部分ローディング**: 該当要素のみスピナー表示

### エラーハンドリング

- **バリデーションエラー**: フィールド直下にエラーメッセージ表示、フィールドを赤枠でハイライト
- **APIエラー（400, 401, 403）**: トースト通知でエラーメッセージ表示
- **APIエラー（500）**: トースト通知で「サーバーエラーが発生しました。しばらくしてから再度お試しください。」を表示
- **ネットワークエラー**: トースト通知で「ネットワークエラーが発生しました。接続を確認してください。」を表示

### トースト通知

- **成功時**: 緑色のトースト通知（数秒で自動消去）
- **エラー時**: 赤色のトースト通知（数秒で自動消去）
- **情報**: 青色のトースト通知（数秒で自動消去）
