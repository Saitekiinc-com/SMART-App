# 10_スタイル設計

## 目的

07_コンポーネント設計 で定義したコンポーネントおよび画面レイアウトに適用する、色・タイポグラフィ・スペーシング・コンポーネント別の見た目・レスポンシブ・アクセシビリティを定義する。スタイルの一貫性・保守性を確保し、実装時に参照しやすいスタイル仕様を定める。

---

## 1. デザイントークン（設計トークン）

05_フロント側処理フロー（トーストの色・エラー時の赤枠）に準拠。CSS 変数または Tailwind テーマに紐づけられる形で定義する。

### 色

| トークン名 | 用途 | 目安 | 備考 |
|------------|------|------|------|
| primary | プライマリボタン・リンク・FAB | 青系（例: #2563eb） | メインアクション |
| primaryForeground | プライマリ上の文字 | 白（#fff） | - |
| secondary | セカンダリボタン・背景 | グレー系（#f1f5f9） | キャンセル・戻る |
| success | 成功トースト・成功状態 | 緑（#22c55e） | 05: 成功時は緑色のトースト |
| error | エラートースト・エラー枠・危険ボタン | 赤（#ef4444） | 05: エラー時は赤トースト、フィールドを赤枠でハイライト |
| info | 情報トースト | 青（#3b82f6） | 05: 情報は青色のトースト |
| background | 画面背景 | #fff / #f8fafc | - |
| surface | カード・モーダル背景 | #fff | - |
| text | 本文テキスト | #1e293b | - |
| textMuted | 補助テキスト | #64748b | - |
| border | 枠線・区切り線 | #e2e8f0 | - |
| borderError | エラー時の入力枠 | error と同じ | 05: 赤枠でハイライト |

### タイポグラフィ

| トークン名 | 用途 | 目安 |
|------------|------|------|
| fontFamily | 全体 | sans-serif または Noto Sans JP。MVP ではシステムフォント可 |
| fontSize | 本文・見出し | xs 12px, sm 14px, base 16px, lg 18px, xl 20px, 2xl 24px |
| fontWeight | 本文・見出し | 400 / 500 / 600 / 700 |
| lineHeight | 行間 | 1.5（本文）、1.25（見出し） |

### スペーシング・角丸・シャドウ

| 種別 | 目安 | 用途 |
|------|------|------|
| space（4px ベース） | 4, 8, 12, 16, 24, 32, 40, 48px | 余白・パディング・マージン |
| コンポーネント間 | 16px〜24px | 07 のコンポーネント間 |
| radius sm/base/lg | 4px / 8px / 12px | ボタン・入力・カード・モーダル |
| shadow sm/md/lg | 軽い〜中程度の box-shadow | カード・モーダル・ドロップダウン |
| transition | 150ms〜200ms ease | ホバー・フォーカス・モーダル表示 |

## 2. コンポーネント別スタイル

07_コンポーネント設計 の共通UIに対応。05 の「赤枠」「トーストの色」を反映する。

| コンポーネント | バリアント・状態 | スタイル方針 |
|----------------|------------------|--------------|
| Button | primary | 背景 primary、文字 primaryForeground、角丸、パディング。ホバー時は少し暗く |
| Button | secondary | 背景 secondary、文字 text。枠線 optional |
| Button | danger | 背景 error または outline で赤枠・赤文字。削除ボタン用（ConfirmDialog variant=danger） |

| Input | 通常 | 枠線 border、角丸、パディング。フォーカス時: 枠線を primary に |
| Input | エラー | 枠線 borderError（赤）。05: バリデーションエラー時は赤枠でハイライト |
| Input | 無効 | 背景 secondary、cursor: not-allowed |
| エラー表示（フィールド直下） | - | 文字色 error、fontSize sm。05: エラーメッセージをフィールド直下に表示 |
| Card（GoalCard, TeamCard 等） | - | 背景 surface、角丸 lg、shadow sm、パディング。ホバー時 shadow 強化 |
| StatusBadge | TODO（未着手） | 背景グレー、文字 text |
| StatusBadge | IN_PROGRESS（進行中） | 背景青系薄、文字青系 |
| StatusBadge | DONE（完了） | 背景緑系薄、文字緑系 |
| VoteUI | 通常・投票済み | ボタン small、投票済みは primary で塗りつぶし等で区別 |
| ToastNotification | success | 背景 success、文字白。05: 緑色のトースト、数秒で自動消去 |
| ToastNotification | error | 背景 error、文字白。05: 赤色のトースト |
| ToastNotification | info | 背景 info、文字白。05: 青色のトースト |
| LoadingState | スケルトン | 背景 secondary で矩形、shimmer アニメ。05: 全画面ローディングはスケルトンスクリーン |

## 3. レスポンシブ・ブレークポイント

- **ブレークポイント（目安）**: 640px（sm）、768px（md）、1024px（lg）、1280px（xl）。Tailwind のデフォルトに合わせると実装しやすい。
- **モバイルファースト**: 基本は 1 カラム。S-04 ダッシュボードのゴール一覧はカードを縦に並べ、md 以上で 2 カラム可。
- **ヘッダー・モーダル**: モバイルではヘッダーをコンパクトに、モーダルはほぼ全画面に近い幅で表示する。
- **フォントサイズ**: モバイルで 14px 本文、lg 以上で 16px など可。MVP では同一サイズでも可。

## 4. アクセシビリティ

- **フォーカス表示**: キーボード操作時にフォーカスが分かるよう :focus-visible で outline（例: 2px solid primary、offset 2px）を付与する。
- **色コントラスト**: 本文テキストと背景は WCAG 2.1 の AA 基準（コントラスト比 4.5:1 以上）を満たす。MVP では「十分なコントラストを確保する」とし、必要に応じて contrast チェックツールで検証する。
- **キーボード操作**: ボタン・リンク・入力・モーダル・ドロップダウンは Tab でフォーカス移動可能とし、モーダルは Esc で閉じるようにする。
- 非機能要件定義書にアクセシビリティの明示的な要件はないため、MVP では上記を前提とする。

## 5. ディレクトリ・ファイル構成方針

- 07_コンポーネント設計 の「components/ui/」に配置する共通コンポーネントのスタイルは、採用するスタイル手法に合わせて配置する。
- **推奨（MVP）**: Tailwind CSS を利用する場合、tailwind.config.ts でテーマ（colors, fontFamily, spacing, borderRadius）を拡張し、デザイントークンを Tailwind のクラスで利用する。グローバルスタイルは app/globals.css に CSS 変数（:root）で色・フォントを定義し、Tailwind の theme から参照してもよい。
- **別案**: CSS Modules の場合は components/ui/Button.module.css のようにコンポーネントごとにスタイルファイルを置く。共通トークンは styles/tokens.css などで CSS 変数として定義する。
- **テーマファイル**: 色・タイポ・スペーシングを一括定義するファイル（styles/theme.ts または tailwind.config.ts の theme 拡張）を 1 箇所にまとめ、components/ui/ の各コンポーネントから参照する。
- **Next.js App Router**: app/layout.tsx で globals.css を import し、Tailwind を有効にしておく。
