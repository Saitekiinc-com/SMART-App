# 08_純粋関数の設計

## 目的

バリデーション・フォーマット・データ変換など、副作用を持たない純粋関数の一覧・責務・入出力を定義する。07_コンポーネント設計・09_カスタムフック設計と整合した実装を可能にし、コンポーネントやフックから共通で利用するユーティリティの仕様を明確にする。

---

## 2. バリデーション関数（03_入力項目・バリデーションに基づく）

### S-01: ログイン/サインアップ

| 項目（物理名） | ルール | エラーメッセージ |
|----------------|--------|------------------|
| email | メールアドレス形式（RFC準拠）、最大255文字 | 正しいメールアドレスを入力してください |
| password | 8文字以上、英字・数字をそれぞれ1文字以上、最大255文字 | パスワードは8文字以上で、英字と数字を含めてください |
| name（サインアップ時） | 1〜100文字 | 名前を入力してください（100文字以内） |
| password_confirm | password と一致 | パスワードが一致しません |

※ Googleログインはフォームバリデーション対象外。

### S-05 / S-07: ゴール作成・編集

| 項目（物理名） | ルール | エラーメッセージ |
|----------------|--------|------------------|
| title | 1〜100文字 | タイトルを入力してください（100文字以内） |
| specific | 10〜500文字 | 10文字以上500文字以内で入力してください |
| measurable | 1〜200文字 | 測定基準を入力してください（200文字以内） |
| achievable | true / false のいずれか | 達成可能かどうかを選択してください |
| relevant | 1〜200文字 | 関連性を入力してください（200文字以内） |
| deadline | 未来の日付、YYYY-MM-DD | 未来の日付を選択してください |
| owner_id | チームメンバーのID（UUID） | 担当者を選択してください |
| status（S-07のみ） | TODO / IN_PROGRESS / DONE | 有効なステータスを選択してください |
| approaches（各 content） | 1〜200文字、最大10件 | アプローチは200文字以内で入力してください（最大10件） |

### S-09: チーム設定

| 項目（物理名） | ルール | エラーメッセージ |
|----------------|--------|------------------|
| name | 1〜50文字 | チーム名を入力してください（50文字以内） |
| description | 最大200文字（任意） | チームの説明は200文字以内で入力してください |
| role | leader / member のいずれか | 有効なロールを選択してください |

### S-02: 招待受諾

※ token / team_id は URL パラメータ。有効期限・未使用はサーバー側で検証するため、クライアント側では形式チェックのみ行うか、API レスポンスに依存する。

## 4. ディレクトリ・ファイル構成方針

- 07_コンポーネント設計の「ディレクトリ・ファイル構成方針」と整合する。プロジェクトルートに **lib/** または **utils/** を置く想定。
- **バリデーション**: lib/validation/ に配置。
  - lib/validation/auth.ts … validateEmail, validatePassword, validatePasswordMatch, validateName（S-01 用）
  - lib/validation/goal.ts … validateGoalTitle, validateSpecific, validateMeasurable, validateRelevant, validateDeadline, validateApproaches, validateGoalForm（S-05, S-07 用）
  - lib/validation/team.ts … validateTeamName, validateTeamDescription, validateTeamForm（S-09 用）
- **フォーマット・変換**: lib/format/ に配置。
  - lib/format/status.ts … formatStatusLabel, formatRoleLabel
  - lib/format/date.ts … formatDateDisplay, formatDateTimeDisplay
- **API ボディ組み立て**: lib/api/ に配置。
  - lib/api/goal.ts … buildGoalCreateBody, buildGoalUpdateBody（06_呼び出すAPI の型定義を import して利用）
  - lib/api/team.ts … buildTeamUpdateBody
- **命名ルール**: ファイル名は camelCase または kebab-case。関数名は camelCase。戻り値は { valid, error? } で統一すると 09_カスタムフック設計 で扱いやすい。
- **型定義**: フォーム値の型（GoalFormValues 等）は types/ または各 lib/ 配下で定義し、06_呼び出すAPI のリクエスト型と整合させる。
